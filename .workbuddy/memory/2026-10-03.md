# 2026-10-03

## 实现 Moyu WebSocket 图片中转站

按 `开发说明.txt` 的需求落地：ComfyUI 推 base64 图片 → Python 服务端 → 网页客户端看图 + 保存。

### 产出

- `server.py` —— aiohttp 双端口服务
  - **8001** WebSocket：收 ComfyUI 推送（与 `clientExample.js` 的 `PORT` 一致，原文件不用改）
  - **8080** HTTP：网页 UI + `/api/history` `/api/stats` `/media/{id}` `/download/{id}` `/api/clear`
  - 网页端 WS 复用 8080 的 `/ws`，不额外占端口
- `webpageClient/`（index.html + style.css + app.js）—— 暗色+撞色 UI，实时上墙 / 灯箱 / 单张下载 / 浏览器端 ZIP 打包
- `tools/test_client.py` —— 模拟 ComfyUI 推图，纯代码生成测试 PNG（不依赖 Pillow 绘图）
- `tools/verify.py`（后端 17 项）、`tools/verify_frontend.js`（前端 35 项，DOM 桩）
- `README.md`、`requirements.txt`

### 关键技术决策

- **落盘走 `asyncio.to_thread`**：写文件是阻塞 IO，直接 await 会卡住事件循环，批量推大图时广播会延迟
- **魔数嗅探代替扩展名判断**：ComfyUI 给什么格式就存什么格式
- **尺寸读取双通道**：Pillow 可选，没有就退回手写 PNG/GIF/BMP 头解析 → Pillow 只是增强不是硬依赖
- **浏览器端打 ZIP**：用 File System Access API 在本地 store 模式打包，服务端不为打包占内存；不支持的浏览器退回逐张下载
- **卡片用 `object-fit: contain` 而非 `cover`**：看图工具不能裁掉画面内容（首版用 cover 被截图发现问题后改掉）
- **历史裁剪联动删文件**：超 `--history-limit` 时内存索引和磁盘文件一起清，不留孤儿文件

### 踩过的坑

1. `ImageStore.__init__` 写了 `self.dir.mkdir()`，但字段叫 `cfg.save_dir` → AttributeError
2. `/api/history` 直接把 `ImageRecord` 对象塞进 `json.dumps` → `TypeError: not JSON serializable`
   → 加了统一的 `json_dumps()` + `_json_default()` 自动展开 dataclass
3. `web.Response(content_type="application/json; charset=utf-8")` → aiohttp 3.x 报
   `ValueError: charset must not be in content_type argument`
   → 改成 `content_type="application/json", charset="utf-8"`
4. `document.write` 的演示页被 SPA fallback 拦下返回 index.html（这是**正确**行为，不是 bug）
   → 静态演示页要放 `/static/` 下才能访问

### 验证结论

- 后端 17/17、前端 35/35 全通过
- 无头 Chrome 截图确认：图片墙完整显示不裁切、灯箱竖图完整呈现、统计/连接状态正确
- base64 四种写法（纯串 / data URI / 含换行 / 缺 padding）均解码一致

## 第二轮：启动脚本 + WS 连接复用 + 在线客户端列表

### 停止后台服务
`TaskStop` 干掉 shell 后，8001/8080 仍被 python 子进程占着 → 需额外
`MSYS_NO_PATHCONV=1 taskkill /F /PID <pid>`。

### 新增文件
- `run.bat` / `run.sh`：探测 Python（优先 `.venv`）→ 装依赖 → 查端口 → 启动。
  沙箱**禁止从 bash 调 cmd.exe**，所以 run.bat 只能逐条逻辑验证，没法真跑。
- `tools/verify_clients.py`（29 项）、`tools/verify_ws_reuse.js`（28 项）
- `webpageClient`：右侧滑出式客户端面板（`👥` 按钮打开，徽标显示在线数）

### clientExample.js 改造要点
- 连接挂 `globalThis.__moyuWsManager` 做单例：OPEN 直接 send /
  CONNECTING 排队等 open 补发 / 异常断开按 1s→15s 退避重连 / 20s 心跳
- **必须包在 IIFE 里**：ComfyUI 每次跑工作流都重新执行整个脚本，
  不包的话第二次执行直接抛 `SyntaxError: Identifier 'HOST' has already been declared`
  （这是写测试时真跑出来的 bug，不是猜的）
- 对外 API 挂 `globalThis`：moyuSend / moyuSendFrom / moyuDisconnect / moyuStatus
- 保留了原来的 `find()` 节点索引

### 本轮修掉的两个真实 bug

1. **并发 send_str 打断连接**（最隐蔽）
   aiohttp 不允许对同一个 socket 并发 `send_str`。「A 断开」和「B 接入」
   同时触发 `broadcast_clients()`，导致 B 刚连上就被打断 ——
   客户端只收到 `clients` 收不到 `hello`，之后全是 CLOSED。
   修法：`Broadcaster` 维护 `_send_locks[ws]`，单播和广播都按连接取锁串行化。
   **教训：加广播功能时必须同步想「有没有并发写同一 socket」**。

2. **中文客户端名被截断**
   复用了给文件名用的 `safe_stem()`（ASCII 白名单），导致 `窗口A` → `A`。
   分离出 `clean_client_name()`：只剔除控制字符和路径分隔符，保留 Unicode。

另外把消息顺序改成先 `hello`（带 `self_id`）再广播名单，
前端不再靠名字猜「哪个是我」。

### 写测试的坑
- 测试断言不能假设「起始 0 个客户端」—— 用户可能开着网页（本次就被
  preview 面板的连接干扰过）。改成只校验本测试自己建立的 id。
- 客户端连接期间会累积多条广播，`recv_until` 要带 pred 过滤，
  否则会读到过期的那条。
- 推送计数随 `type=image` 广播下发（不是 `type=clients`），两种都要接受。

### 验证结论
四套测试合计 **127 项全通过**（后端 17 / 客户端列表 29 / 前端 53 / 连接复用 28），
并用无头 Chrome 截图确认客户端面板渲染正确（自己标「我」、推送端带计数）。

## 第三轮：修复 run.bat 编码（双击闪退）

### 根因（tools/_check_bat.py 体检确认）
1. **纯 LF 换行**：105 行 0 个 CRLF —— Write 工具落盘是 LF，
   cmd.exe 要求 CRLF，LF-only 会让 `goto`/标签失效 → 双击闪退。
2. **行 37 `if %errorlevel!==0`**：少收尾 `%`，纯语法错误
   （其他 `!errorlevel!` 是合法延迟展开；「括号不配对」是跨行块的误报）。

### 修法
`tools/gen_run_bat.py` 用 Python 字节级重写：UTF-8 无 BOM + 全 CRLF（89 行全对）。
控制流简化：`where x && set` + `if defined PY goto` + `if errorlevel 1`（块内不依赖
`%errorlevel%` 提前展开）+ `call :port_check` 子过程。

### 验证（这次是真跑，不是模拟）
- 沙箱从 bash 调 `cmd.exe` 被拦，但 **Python `subprocess.run(["cmd","/c",...])` 不被拦**：
  - `_probe_bat.py`：复刻探测+端口逻辑的真 bat，cmd 执行 6/6 通过
  - `_e2e_bat.py`：真跑 `run.bat`，HTTP 服务被拉起 ✓，taskkill 杀进程树后退出 ✓
- 通用教训已写入用户级记忆「Windows 批处理编码铁律」。

### 临时文件
`tools/_check_bat.py`、`_probe_bat.py`、`_e2e_bat.py`、`_bat_probe.bat`、
`gen_run_bat.py` —— 生成器保留，其余体检/验证脚本可删可留（都有独立价值）。
